# 地贫科研团队 · Thalassemia Research Team

一个面向地贫与血液遗传病研究的协作型专家团。你把需求说清楚，主理人「大管家」把活拆开，分给对应的成员去做，最后汇总成一份能直接用的结果。

**特点**：团队成员的构成、名字、工作文件夹位置、引用与排版偏好，全部在第一次使用时问过你之后固化下来，之后不用重复交代。

---

## 一、第一次用：三步

### 第 1 步 · 装上

把整个 `thalassemia-research-team` 文件夹放进 WorkBuddy 的专家目录：

```
<你的用户目录>/.workbuddy/plugins/marketplaces/my-experts/plugins/
```

放好后在 WorkBuddy 的「专家」里就能看到「地贫科研团队」。

### 第 2 步 · 建档（只做一次）

打开专家，直接说：

> 我是第一次使用，请先引导我完成团队初始化。

大管家会分三轮问你 8 个问题，每题都有选项，拿不准就选推荐项：

| 轮次 | 问什么 |
|------|--------|
| 第一轮 | 怎么称呼您、研究方向、用什么语言交流 |
| 第二轮 | 给主理人起什么名字、团队叫什么、工作文件夹放哪 |
| 第三轮 | 先配几个成员、引用与排版按哪套来 |

答完会给你一张确认表，你确认后它就在你指定的位置建好文件夹。

**这些问题只问一次。** 之后每次打开，它先读档案，直接知道你是谁、研究什么、该怎么称呼你。

### 第 3 步 · 开始用

直接用中文说需求，不用记命令：

- 「帮我查近五年地贫铁过载的文献，整理成表」
- 「这个数据帮我做差异分析并出图」
- 「按这个思路写一份基金标书的研究背景」
- 「分析这篇论文，画一张机制图」
- 「我要改团队配置，把维护师去掉，加一个统计师」

## 二、团队成员

默认 9 人，**可增可减可改名**。

| 名字 | 职业 | 干什么 |
|------|------|--------|
| 大管家 | 科研调度总监 | 拆任务、分派、盯进度、汇总（主理人，不代写专业内容） |
| 馆长 | 知识库馆长 | 论文入库、文献检索、引用核验、引用网络 |
| 地贫管家 | 地贫研究专家 | 实验设计、文献深度分析、方向判断、机制推演、综述 |
| 代码专家 | 数据分析工程师 | 脚本、统计、数据清洗、可视化、小工具 |
| 科研顾问 | 科研项目规划师 | 选题、项目背景、临床数据需求、基金标书 |
| 商业巨头 | 商业策划师 | 商业计划书、商业模式、财务预测、成果转化 |
| 医学教授 | 医学讲师 | 教材讲解、考纲解析、知识点整理、试题解析 |
| 绘图师 | 科研绘图师 | 流程图、机制图、配图（PPT 原生形状，可编辑） |
| 维护师 | 服务器环境运维工程师 | 环境搭建、镜像源、依赖安装、环境审计 |

### 改团队

| 想做的事 | 直接说 |
|---------|--------|
| 加一个岗位 | 「加个统计师，负责样本量估算和检验效能」 |
| 去掉一个岗位 | 「医学教授我用不上，先关掉」 |
| 改名字 | 「把绘图师改叫美工」 |
| 改团队名 | 「团队改名叫血液病科研团队」 |

改动会同步写进档案，下次不用再说。

## 三、随包附带的技能

| 技能 | 用途 |
|------|------|
| `team-onboarding` | 首次建档、改团队配置、成员增删改、工作区体检 |
| `academic-research-skills` | 学术全流程：找文献、读文献、写论文、模拟审稿（含 PRISMA 系统综述） |
| `pubmed-verifier` | 引用验真：判断 PMID 是否真的指向这篇论文，检出 AI 编造引用 |
| `academic-figures` | 论文配图：22 种图表（KM 曲线、ROC、森林图、热图、韦恩图等），期刊色板与投稿预设 |
| `anti-defensive-writing` | 论文去防御腔：把「自我削弱的写法」改成有主张的写法 |
| `docx-anti-defensive-writing` | 上一条的 Word 落地版：定点改写、保留格式、出修改清单 |
| `agent-team-delivery-discipline` | 多智能体协作的交付纪律：防止假成功、口径漂移、记录失真 |

## 四、工作文件夹长什么样

建档时在你指定位置生成，结构固定：

```
<你指定的目录>/
├── README.md              说明
├── 团队宪章/
│   ├── team-profile.json  机器读的档案（成员、偏好、路径）
│   └── 团队宪章.md        人读的约定
├── .workbuddy/memory/     长期记忆与每日流水
├── 成员/<名字>/项目/      各成员的产出
├── 项目/                  长期课题
├── 任务/<年-月>/          一次性任务的过程文件
└── 共享/
    ├── 交付/              成品
    └── 技能库/            自建技能
```

根目录只保留这 7 项，临时文件一律归到 `任务/` 里。这条纪律是为了一年之后还能找到东西。

## 五、引用规范（默认，可在建档时改）

正文引用默认按中文医学论文的习惯来：

1. 观点句末标 `（pmid：XXXXXXX）`，红色字体，**句号在括号之外**
2. 每条 PMID 都经过 `pubmed-verifier` 核验，核验不通过的不用
3. 优先近 5 年文献；奠基性文献可放宽年限但要注明
4. 排版默认宋体／Times New Roman 四号、标题三号加粗、1.5 倍行距、首行缩进 2 字符、A4

初次建档时如果选了 GB/T 7714 或作者-年份制，就按你选的来。

## 七、分享给别人

打包整个目录发给对方，对方解压后放进自己的专家目录即可：

```
<用户目录>/.workbuddy/plugins/marketplaces/my-experts/plugins/thalassemia-research-team/
```

对方第一次打开时会走一遍建档，各自的数据互不影响（档案存在各自的工作文件夹里，不随包走）。

---

## 八、几点说明

- **档案与数据都在你的本地文件夹里**，跟着专家包走的只有提示词与技能，不含任何人的研究数据。
- **凭据不进档案**。服务器密码、密钥这类东西不写入任何文件，需要时由你当场提供、用完即弃。
- **审稿功能仅供自审**。模拟审稿的产出不能当作真实期刊意见使用。
- **引用核验只能证明"这篇存在且指向正确"**，不能证明"这篇支持你的论点"。论点与证据的对应关系要自己把关。
