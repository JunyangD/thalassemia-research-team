# 学术科研全流程技能包（academic-research-skills）

把上游 **Academic Research Skills（ARS）** 的四套件封装为一个技能，服务科研团队的日常工作流。核心立场：**AI 是副驾驶，不是飞行员**——它承担查文献、核引用、查逻辑一致性这些重活，但研究问题、方法选择、数据解释、论点归属始终由研究者本人负责。

## 一、四条主路由

先判断老板要的是哪条线，再去读对应的 PROTOCOL 全文，按其中的模式定义与智能体分工执行。**不要凭本文件直接开工**，本文件只是入口。

| 老板想干的事 | 走哪条线 | 入口文件（先完整读它） |
|---|---|---|
| 找文献、读文献、文献综述、系统综述、事实核查、选题方向 | **深度调研** `deep-research` | `references/upstream/deep-research/deep-research-PROTOCOL.md` |
| 写论文、写综述、拟提纲、写摘要、引用格式转换与核验、返修答审 | **论文写作** `academic-paper` | `references/upstream/academic-paper/academic-paper-PROTOCOL.md` |
| 模拟审稿、以审稿人视角评估、投稿前自审、返修后复审 | **同行审稿** `academic-paper-reviewer` | `references/upstream/academic-paper-reviewer/academic-paper-reviewer-PROTOCOL.md` |
| 从选题一路做到定稿，需要全流程串联 | **全流程编排** `academic-pipeline` | `references/upstream/academic-pipeline/academic-pipeline-PROTOCOL.md` |

> 编排线内部会调用另外三条线；若只做单点任务，别走编排线，直接从对应线进入更省成本。

## 二、每条线能做什么（速查）

**深度调研（13 智能体 / 8 模式）**
全模式研究、快速简报、论文解读、文献综述、事实核查、三段式文献扫描、苏格拉底式选题对话、系统综述（PRISMA 2020，可选荟萃分析）。覆盖研究问题提炼、方法学设计、系统检索、来源验证、跨来源综合、偏倚风险评估、荟萃分析、APA 7.0 报告汇编、编辑审阅、魔鬼代言人质疑、伦理审查、后续文献监测。

**论文写作（12 智能体 / 11 模式）**
全流程写作、结构规划、提纲、修订、修订教练、摘要、文献综述、格式转换、引用检查、AI 使用声明、答审审计。支持 6 种论文类型、5 种引用格式、双语摘要、LaTeX/DOCX/PDF 输出，含风格校准（模仿本人历史文风）、写作质量检查与反模式 IRON RULE 标记。

**同行审稿（5 席面板）**
期刊适配审稿人 + 3 位同行审稿角色 + 魔鬼代言人，按领域专长分流。支持完整审稿、复审（验证）、快速评估、方法学专项、苏格拉底引导、审稿人校准。按 0-100 分给出分档结论：>80 录用、65-79 小修、50-64 大修、<50 拒稿，并附修订路线图。

**全流程编排（10 阶段）**
研究 → 写作 → 完整性检查 → 审稿 → 返修 → 复审 → 再返修 → 终检 → 定稿。在 Stage 2.5 与 4.5 设两道不可跳过的强制质检门。

## 三、执行前必须遵守的学术规范

以下是默认基线，**优先级高于上游 ARS 的默认行为**。用户档案 `team-profile.json` 的 `preferences` 与本节冲突时，**以用户档案为准**。

1. **引用格式**：观点句末标 PMID，写作 `（pmid：XXXXXXX）`；**句号在括号之外**；引用文字用**红色字体**。
2. **文献时限**：默认限近 5 年 PubMed；**奠基性文献可放宽年限**，但须注明其为奠基文献。用户若指定某主题不限年限，按档案执行。
3. **禁止虚构引用**：任何 PMID 必须经 `pubmed-verifier` 逐条核验后才可写入正文。ARS 自带的引用核验流程可作为第一道筛，**但不替代**逐条验证。核验不通过的引用一律剔除，不得保留待查。
4. **去 AI 痕迹**：禁用「值得注意的是」「综上所述」「首先/其次/最后」「总而言之」等模板化表达；避免「xx-xx」式并列结构；句长要有起伏，不要通篇等长句。
5. **研究视角**：以用户档案里的 `owner.field` 为准。不要替用户假设他站在哪个视角、关心哪类患者——这由研究者本人定。
6. **交付格式**：默认中文宋体（西文 Times New Roman）四号、标题三号加粗、1.5 倍行距、首行缩进 2 字符、A4；参考文献按 GB/T 7714；优先输出 docx。用户档案 `preferences.docFormat` 优先于本默认。
7. **诚实标注证据强度**：结论分「有直接证据」「有间接证据」「假设级」三档写明。阴性结果、样本偏小的探索都可以写，但强度必须与数据匹配。

## 四、输出与交接规范

- 写作线产出的正文，交由**馆长**核验引用与入库；领域判断交**地贫管家**；选题与立项论证交**科研顾问**。ARS 负责流程编排，团队角色负责领域责任。
- 审稿线产出的审稿意见，仅作为**投稿前的自审**使用，不得冒充真实期刊审稿意见对外使用。
- 交付物落到工作区 `项目/<项目名>_<YYYYMMDD>/` 或 `共享/交付/`，具体路径由主理人指定。
- 大段参考资料留在本技能 `references/` 内，不要把上游 PROTOCOL 全文抄进交付文档。

## 五、边界与风险

- **许可证**：上游 ARS 为 **CC BY-NC 4.0**——署名、非商业性使用。商用场景须另行获得作者授权。署名信息见 `NOTICE.md`、`SOURCE.md`。
- **能力边界**：ARS 不替代实验设计、伦理审查、署名责任与专家判断。审稿分为模拟结果，不等于期刊决定。
- **引用核验的置信度**：任何引用核验流程都只能证明「这条引用存在且指向该论文」，不能证明「该引用支持当前论点」。论点与证据的忠实度需人工复核。
- **上游脚本未随包**：ARS 的 hooks / commands / 自动化脚本是 Claude Code 专属运行时，本包未包含；其引用核验依赖外部学术 API（Semantic Scholar / OpenAlex / Crossref / arXiv），在无网络环境下会降级为人工核验。
